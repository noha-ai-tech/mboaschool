# ÉCOLES237 — Normal local Supabase differences

This document classifies differences that may be accepted during a future
successful local empty-database replay. No final catalog was produced in the
failed attempt, so these are comparison rules, not observed results.

## Differences normally acceptable

- Database and object OIDs.
- Physical relation filenames, pages, statistics and planner estimates.
- Local Docker container identifiers and internal network addresses.
- Local project URL, API keys, JWT signing material and generated secrets.
- Supabase-managed schema objects whose version follows the local CLI image:
  `auth`, `storage`, `realtime`, `extensions`, `graphql`,
  `supabase_functions` and migration-management internals.
- Owners of Supabase-managed internal objects when the local image uses a
  version-specific service role.
- Extension binary versions when functionally compatible and outside
  application-owned `public` objects.
- Creation timestamps and statistics timestamps.
- Empty local Auth/Storage operational rows that are generated by the local
  stack itself.

## Differences not acceptable

- Missing, additional or structurally different application tables in
  `public`.
- Different public enum labels or enum ordering.
- Different columns, defaults, nullability, constraints or foreign-key actions.
- Missing, additional, invalid, partial or differently ordered application
  indexes.
- Different application function signatures, bodies, volatility, security
  mode, owner, ACL or `search_path`.
- Different application triggers, events, activation state or target
  functions.
- Different RLS enablement, policy roles, commands, `USING`,
  `WITH CHECK`, permissive/restrictive mode or direct grants.
- Presence of `public.current_establishment_id()` after the final PRO-03 gate.
- Presence of `public.is_own_establishment(uuid)` after PRO-04 lot 1.
- Missing PRO-04 hardened ACLs/search paths or eight FK indexes.
- Anonymous writes reopened after PRO-05.1.
- A non-`VOLATILE` or incorrectly granted
  `get_admission_by_tracking(text,text)` after PRO-05.2.
- Any business row created by baseline/replay.
- Any count other than five for the explicitly configured application Storage
  buckets.
- Any migration-history version other than the 41 canonical versions in the
  isolated replay database.

## Future comparison method

A successful rerun must normalize only the acceptable environment-owned
differences above. Application-owned definitions must be compared through the
PostgreSQL catalogs and `pg_get_*def` functions without text-format-only
assumptions.
